## What DK2 does, in one paragraph

The front end is an ordinary game session: `FrontEnd3DLevel` loads in game mode 5
with no HUD, the Hero Gate FrontEnd room spawns the props (`0x004DEF30`), and a
per-frame state machine (`0x005384F0`) flies the camera between stations on paths
250–274 and opens a page when a path ends. Pages are a static table of 32 in the
executable (`0x006AE4E0`) drawn by the same GUI system as the in-game HUD; labels
are `Text.str` ids and hit-testing is by rectangle. Only the campaign map pieces
(objects 0x66 and 0x73, `0x00538D00`) and My Pet Dungeon pieces (0x85,
`0x005392E0`) are picked in 3D. New Campaign resets the profile and flies to the
map; a level starts only from a click on its map piece. Starting a level
sets a start request, a game mode, a level name and a return page, and the session
exits; after the level the front end reloads and routes by the return page to the
statistics screen and back to the right station. Progress is a profile kept in the
registry and re-saved on every change.

## Architecture

Follows `AGENTS.md` and ADR-0002: no Unity in `src/`.

- **Rules in `src/`.** Campaign progression (status values, unlocks, branches,
  secrets, attempts, evil rating, transfer creature) is a pure rule set over a
  profile record, with tests, beside the simulation. The transfer creature's
  arrival and the win sequence are simulation changes (hash bumps).
- **Front-end flow in `DK2.Presentation`.** The page table, the station state
  machine and the return-page routing are presentation state, Unity-free and tested
  headlessly, like the step 6 HUD.
- **Unity draws and forwards input.** It renders the front-end level with the
  classic-look renderer, plays the camera paths, draws pages with the step 6 widget
  and `.bf4` text code, and owns scene switching between front end and level.
- **Our own profile file**, not the registry, holding the same fields with the same
  meanings. An optional one-time import from an installed DK2's registry carries
  the owner's real progress over.

## Owner decisions (2026-10-23)

1. **Movies:** our own C# decoder reads the install at run time. No ffmpeg and no
   converted copies of install files on disk.
2. **Sound:** decoded in C# at load time, in memory; no cache.
3. **Registry import:** supported. On first run the profile may be filled from an
   installed DK2's registry values (campaign progress only; original saves still
   load terrain only, Q182).
4. **Menu labels:** see ADR-0539 for the owner's font/fallback and sizing decision.

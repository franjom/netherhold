## What DK2 does, in one paragraph

The front end is an ordinary game session: `FrontEnd3DLevel` loads in game mode 5
with no HUD, the Hero Gate FrontEnd room spawns the props (`0x004DEF30`), and a
per-frame state machine (`0x005384F0`) flies the camera between stations on paths
250–274 and opens a page when a path ends. Pages are a static table of 32 in the
executable (`0x006AE4E0`) drawn by the same GUI system as the in-game HUD; labels
are `Text.str` ids and hit-testing is by rectangle. Only the campaign map pieces
(objects 0x66 and 0x73, `0x00538D00`) and My Pet Dungeon pieces (0x85,
`0x005392E0`) are picked in 3D. New Campaign resets the profile and flies to the
map; a level starts only from a click on its map piece. Starting a level
sets a start request, a game mode, a level name and a return page, and the session
exits; after the level the front end reloads and routes by the return page to the
statistics screen and back to the right station. Progress is a profile kept in the
registry and re-saved on every change.

## Architecture

Follows `AGENTS.md` and ADR-0002: no Unity in `src/`.

- **Rules in `src/`.** Campaign progression (status values, unlocks, branches,
  secrets, attempts, evil rating, transfer creature) is a pure rule set over a
  profile record, with tests, beside the simulation. The transfer creature's
  arrival and the win sequence are simulation changes (hash bumps).
- **Front-end flow in `DK2.Presentation`.** The page table, the station state
  machine and the return-page routing are presentation state, Unity-free and tested
  headlessly, like the step 6 HUD.
- **Unity draws and forwards input.** It renders the front-end level with the
  classic-look renderer, plays the camera paths, draws pages with the step 6 widget
  and `.bf4` text code, and owns scene switching between front end and level.
- **Our own profile file**, not the registry, holding the same fields with the same
  meanings. An optional one-time import from an installed DK2's registry carries
  the owner's real progress over.

## Phases

Sizes are relative: S a day or less, M a few days, L a week or more at the
current pace.

### F1 — Plumbing (S–M)
- [x] `WadArchive`: indexed extraction reaches either duplicate; 31 `FrontEnd.WAD` names
  occur twice and lookup by name returns the second copy.
- [x] BMP reader (42 files), `.444` direct-RGB mode (29 files), and a WAD-to-Unity texture provider. Masked `.444` is refused; see [format evidence](../research/front-end-assets.md#14-444-images-bytes-confirmed-codec-strongly-inferred).
- [x] Campaign profile snapshot/file, optional read-only first-run registry import and runtime `HiScores.dat` read/write (ADR-0538). Rules and menu integration remain later phases.

### F2 — The front-end session (M)
- [x] Unity loads a level by name at run time instead of the inspector's
  `levelName`; the front end and a level are two modes of one runner or two scenes.
- [x] Load `FrontEnd3DLevel` in game mode 5 with no HUD; port the Hero Gate
  FrontEnd room's prop spawning (`0x004DEF30`).
- [x] Port the station state machine (`0x005384F0`) and play paths 250–274 with the
  existing camera-path playback (ADR-0496/0498, front-end flag 0x8).

### F3 — Pages and widgets (M)

- [x] Hover, click, the hover sound hook (0x30F) and Quit confirmation (`0x00536BA0`,
  read; sound playback remains F8).
- [x] Main, Single Player, Options shell, Extras shell and Quit work end to end.

### F4 — Campaign map and briefing (M)

### F5 — The level loop (M–L)

- [ ] Post-win text screen with its Mentor line, then the cutscene (F7); Level 20's

**After F5 the campaign can be played from the menu with no sound or movies.**

### F6 — Save and load (S–M)
- [ ] Load Game page over `WorldSnapshot`; saving from the in-game Options; loading

### F7 — Movies (L)
- [x] A C# TGQ decoder in `src/` (container, TGQ video, EA-XA ADPCM audio) that
  reads `Movies/*.tgq` from the player's install and decodes into memory; nothing
  derived is written to disk. Built in `src/DK2.Data/Media` (`research/movie-format.md`). DKII.EXE's own player (`0x005A8F70`/`0x005A8FB0`) is
  the primary source; published format descriptions corroborate.
- [x] Unity playback proof of concept (`ClassicMoviePlayer`, menu DK2 > Movies > Play Bullfrog Intro; frames to a texture, audio to a streamed clip, paced by the audio position, Esc/Enter/Space/mouse skip; the next frame decodes ahead on a worker). The owner ran it on 2026-10-23: picture and sound play and feel in sync; one run logged 7.4 ms average decode, frames shown 10 ms after due by the mixer clock, and a mixer up to 85 ms ahead of the speakers (not compensated). Not compared side by side with DK2.
- [ ] Start-up: title screen 10 s, `BullfrogIntro`, `Intro`, path 250; skip keys;
  idle replay after 180 s; cutscenes after wins; View Movies in Extras.

### F8 — Sound (M, music L)
- [ ] MPEG Layer I and II decoding of SDT entries in memory at load time
  (front-end and GUI sounds are Layer I, speech and music Layer II); try NLayer
  (MIT) on one file of each layer first, else our own decoder. Bank map readers.
- [ ] Front-end and HUD sounds, then the Mentor's speech (also serves action 24),
  then music, whose segment sequencer still needs reading from the binary.

### F9 — Options (S–M)
- [ ] Graphics, Sound and Control pages bound to our settings. A value DK2 stored
  for Direct3D (device GUID, screen mode) maps to its Unity equivalent or is
  dropped, and the page says so.

### Deferred
- Skirmish lobby (M13) and multiplayer pages (M14): about 200 unread functions,
  mostly session and lobby code. The buttons exist and are disabled until then.
- My Pet Dungeon (its 7 maps and the MPD table), Today's Top Keepers, Credits,
  DK3 Trailer: after F5, cheap once the page system works.
- The 2D fallback front end (`-FE`, slow machines): not built; no current machine
  needs it.

## Owner decisions (2026-10-23)

1. **Movies:** our own C# decoder reads the install at run time. No ffmpeg and no
   converted copies of install files on disk.
2. **Sound:** decoded in C# at load time, in memory; no cache.
3. **Registry import:** supported. On first run the profile may be filled from an
   installed DK2's registry values (campaign progress only; original saves still
   load terrain only, Q182).
4. **Menu labels:** see ADR-0539 for the owner's font/fallback and sizing decision.

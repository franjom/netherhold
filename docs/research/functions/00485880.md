It is the only reader of variable 132, EPLossSecondWhileNotTraining (global 0x006F2904), and calls the adder 0x00457880 with the negated value unless the current category is 13; the category comes from 0x00478050, which looks through a category 2 utility state to the saved state at creature+0xDF (training.md section 8). It is called from the creature update 0x00488930 at offset +0xC54, so it runs per tick, not per second as the variable's name says: a non-zero value would drain four times the named rate (section 6.2). The variable ships as 0, so the mechanism is live but switched off (balance-variables-in-the-binary.md). Ours only exposes the shipped zero as TrainingRules.ExperienceLostPerSecondWhileNotTraining; no drain is simulated, so READ.

Callback of cursor state 5 (PickAxeTag) in the 52-byte state table at 0x0068F638 (callback word at +0x1C of each record; the state table binds it to PickAxeTag). Event 0, sent by 0x0040ABC0 on a request: adopts the requested state and restarts the clock. Event 1, sent by 0x0040ABC0 right after event 0 and by 0x0040AAE0 after a wrap: the sound below. Event 2, completion from 0x0040AAE0: sets the current and requested state to 6 (PickAxeHoldTagging) and returns 1. Other events return 1 and do nothing.

Sound (disassembly 0x0040E332..0x0040E392), on event 1 only: event 0xEC twice. First nonpositional (manager slot +0x24, handle 0) in the category at +0x195 of the definition returned by slot +0x70 with argument 2; then positional (slot +0x20, handle 0) in the HAND category (manager slot +0x58) at the pick record's world position (+0x1078/+0x107C) with height 0x2000. The definition from slot +0x70 with argument 2 is a terrain definition's (+0x195 is the terrain category), and the install has no TERRAIN_* category loaded from an SFX.map with group 0xEC: among the non-speech SFX.maps only `hand` has it (one sample), so the nonpositional request is silent and the tag sound is HAND/0xEC. The neighbouring callback 0x0040E520 requests HAND/0xC5 the same way, latched by byte 0x006CE95C.

State 5 is requested only by Hand_Click (0x004075E0), at 0x00407A2C and 0x00408112: a press on a Taggable tile in tool modes 0 and 3, the same arms that start the drag (+0x13F0 = 1 tag, 2 untag). The tag or untag command is posted at release and plays nothing, so the sound is on the press, once per drag; untagging starts the same state. Built as HandCursorFeedback.Play(Tag); see sound-effects.md section 6.

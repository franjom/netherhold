The terrain-change routine, taking (x, y, terrain, owner, ...) with about ten callers: the KWD map loader, the save loader, the tile-work applier `0x00452F60`, the room split, and the heart and defeat routines. A non-ownable result is given the neutral player `[0x006F2548]` whatever owner is passed (`0x0044FDBF` tests the new terrain's `+0x17B` bit 2, then `Tile_SetOwner` `0x004559D0` at `0x0044FDD9`), CONFIRMED by the Level 1 capture (tile-work.md) and the binary (Q514). Built in TileWork.cs; DefeatRules.cs, RoomRules.cs and TriggerExecutor.cs now give the neutral player too (ADR-0362). It also writes the navigation byte from the terrain flags (Solid gives 8, then bits 7 and 8 give 1 and 3; structure-blocks.md §5.4, auto-placed-furniture.md §4), recomputes the claim pre-filter via `0x004502D0` (imp-task-stealing.md §3), clears the explored bit on `UnexploreIfDugByAnotherPlayer` terrain taken by another player and sets it for tiles the local player gains (fog-reveal-sources.md §3.2), and posts wall-torch refresh commands (wall-torches.md §6). Those other effects are read from the binary, not captured; it does not touch the imp task pool (imp-claim-path.md §4). Bridge posts: command 4 (record +4 = 1) for each of the four neighbours that pass 0x00452D80, N, E, S, W from 0x006BC350 (0x00450108), then for the tiles two steps away (0x0045019D), when the new terrain is not Solid; command 3 with +4 = 1 for the tile when argument 5 is set (0x00450288).

It does not write the room's Health (+0x35): StoreAt over every block finds that word written only by Room_Construct, the applier 0x004E5300 and Room_SetHealth, so a room handed over here keeps its damage, and a conversion's reset to StartingHealth times Size is the applier's own step after this call.

After retagging each slab, requests effect8 at that slab centre, Z0, heading0 and new owner; one request per chain tile on transfer, including Portal capture. See room-construction-effects.md section6.

The trigger caller is world action 49 (CHANGE_ROOM_OWNER): the arm 0x005197F7 of 0x00518AD0 calls this function directly at 0x00519860 with the room found at the one-based tile and the player record's tag as the new owner, not through the applier 0x004E5300. So that action keeps the room's damage; Level17's three handovers rely on it (openkeeper-pr-audit-1000-1110.md, PR 1090). The arm skips a tile with no room or a room the player already owns, and does not test that the player exists. Built as `TriggerExecutor.ChangeRoomOwner`, which calls `RoomHealthRules.TransferOwnership` directly (ADR-0760).

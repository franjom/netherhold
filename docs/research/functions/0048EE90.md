`__thiscall` on the creature with tile coordinates (x, y) used as given (not shifted). It fetches the cell through World vtable +0x1D8 (World_TileCell 0x00508FC0, no bounds test) and takes the tile owner as cell word +8 & 0xFFF. If `+0x4A3` is already non-zero, or the tile owner is the creature's own (`+0x28`) or the neutral player `[0x006F2548]`, it zeroes `+0x4A3` and returns (so a second toggle always ends the disguise). Otherwise it calls 0x00455990 (UNREAD) and walks the active player list (the head word through the actual owner's player `+0x10FD`, which is the world +0x7A players manager; next player `+0x3A`) and each player's creatures (player `+6`, next `+0x10`). For each creature whose effective owner (`+0x455` when `+0x453` is set, else `+0x28`) is allied with the tile's owner (`Player_IsAllied`) it computes d = (dx^2 >> 12) + (dy^2 >> 12) from this creature (12.12 units, both 64-bit products narrowed). If this creature's Creeping bit (`+0x3E6` bit 12) is set, d = d * pct / 100 with pct the level-scaled `def+0x760` (level 1 raw; else level-stat word at 0x006E4154+0x2A3+2*level times it /100). Seen when d < sight^2 * 0x1000 (signed, strict; sight = watcher `def+0x77B` in tiles) and 0x004512F0(this pos, watcher pos, 0, 1) is nonzero: then `+0x4A3` is zeroed. If nobody sees it, `+0x4A3` becomes the tile owner's player id. No creature-definition flag gates it: any creature the command reaches can sneak.

Two callers: the command 0x1D handler 0x00517270 (the sending player's possessed creature `player+0x134`, packet dwords 0 and 1 as x, y, unvalidated), and `Hand_PickUp` (0x004BC61D) when a keeper other than the owner picks up a creature with `+0x4A3` set: the call then always clears the disguise and the pick-up returns 0. Creeping shortens the distance a watcher needs, so it makes the disguise harder to put on. Not built in src/.

A thiscall on the player with no arguments. It writes `player+0xB53` (the deadline the clock `0x004BE1A0` reads) as the game turn plus `TimeBeforeFirstPayDaySeconds` (`0x006F2611`) times variable 19 (`0x006F2590`), writes `player+0xB4F` with the turn, and sets bit `0x200` of `player+0x76`. Two callers, both passing the creature's owner as `this` and both skipping the call when that bit is already set or when the creature's definition flags `def+0x686` have bit 0 (`IsWorker`): the creature constructor at `0x0048795E` (owner from the thing table by the constructor's owner argument) and a site at `0x0048D24E` that has just handed a creature to a new owner (`creature+0x2A`). So the first payday is armed by the keeper's first non-worker creature, and a keeper that never has one keeps a zero deadline, which the clock treats as no payday. Ours: PaydayRules.ArmOnGain, called from WorldState.SpawnCreature and ChangeCreatureOwner(database, ...), reading a non-zero deadline as the bit (ADR-0295).

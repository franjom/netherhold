Arguments (t, k): edge k of triangle t runs from vertex slot k to slot next(k) (tables 0x0066DA14 = [1, 2, 0] next, 0x0066DA18 = [2, 0, 1] prev); the neighbour u is +6 + 2k and j is u's slot pointing back. Returns 0 if u is -1, if t's constraint bit (k + 3) of +0xD is set, or if u's bit (j + 3) is set, all before any write. Then, before any geometry, it rewrites constraint bits: clears t's bit next(k) + 3 and u's bit next(j) + 3, sets t's bit k + 3 from u's old bit next(j) + 3, and u's bit j + 3 from t's old bit next(k) + 3 (the stores at 0x004CA10D..0x004CA164 precede the orientation tests at 0x004CA1ED and 0x004CA2A2). Only then come two 64-bit orientation tests: with a = t.v[k], b = t.v[next k], c = t.v[prev k], d = u.v[prev j], the shared edge's ends a and b must lie strictly on opposite sides of the line through the apexes c and d (cross(d - c, a - c) > 0 and cross(d - c, b - c) < 0), else it returns 0 with the bits already moved. On a flip: t.v[next k] := d and u.v[next j] := c, so t becomes (a, d, c) and u becomes (b, c, d); t's neighbour k := u's old neighbour next(j), u's neighbour j := t's old neighbour next(k), the new diagonal links t's slot next(k) to u's slot next(j), and the two outer neighbours' back links are repointed. The edge bits 0-2 of +0xD move the same way, the new diagonal taking the old shared edge's bit. Width classes are recomputed for t then u. Returns 1. Callers: the coarsening 0x004CC650, which has already passed the same convexity tests through 0x004CC190 and ignores the result; and the degree reduction 0x004CAF40 and 0x004CBBD0, which call it speculatively around a fan and step on when it returns 0, so there a refused non-convex flip leaves the constraint bits moved. A whole-map build carries no constraint bits, so nothing shows there.

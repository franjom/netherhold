thiscall (door, write). Tile from the door's +0x1A/+0x1E >> 12. Nonzero: byte = [player +0x10FC] << 4, | 4 when definition +0x8B bit 6 (barricade) or +0x111 (lock mode) is nonzero, | 2 when 0x00450FC0(x, y) answers nonzero; written through NavCache_SetTile. Zero: when the cached byte's high nibble is nonzero, NavCache_SetTile(x, y, 0); otherwise nothing. The zero arm never consults the terrain, so a door gone from water or lava leaves floor (0) until Tile_SetTerrain 0x0044FC40, which writes the terrain's byte on every call, next runs on the tile. Level 4 seed 1's dump holds 0 on (24,9)'s water at tick 500, consistent with the hero door the THINGS file places dying there on its first update (LIKELY; Q600). Callers: door init 0x004A5070 (write = not under construction), level start 0x0050BA1A (1 for each door), the cleanup 0x004A5290 (0), 0x004A67C0 (0, then not under construction), the update 0x004A55F0 (two sites), 0x004A55B0, 0x004A66C0, 0x004C3670.

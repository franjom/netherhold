Read 2026-10-01 (decompile). `this` is the room; arguments the start tile and the amount. A ruined room (`+0x9A` bit 0) returns at once. From the start tile it follows the tiles' chain links (tile `+0x4`, wrapping to the room's first slab `+0x2D`) until the amount is gone or the walk is back at the start. On a Heart only the tiles `0x004DA1B0` admits (the rim) are filled.

Per tile: the store pile (object 3 of the room's owner) is found or created (`0x004B7A90(3, …)`); its cap is `0x006F25A8` (Heart tile, 1000) for a live Heart, else `0x006F25A4` (3000). A pile it creates is followed by the room definition's effect `+0x425` (ROOMS file 0x386: Treasury 60 Gold Earn Creation, Heart 0) at the tile centre, Z 0, heading 0, for the room owner, when non-zero; then `0x005558D0(0x800)` on the world stream (line `0x14F`), which sets the pile's current and previous heading `+0xF4` and `+0x102`. Below the cap it takes what fits: the pile (`Object_AddGold`), the room's total `+0x49`, the player's gold (`Player_ChangeGold`) all rise by it. Each walked tile's pile art is then set by `0x004F4440` (thirds of the cap).

Leftover after the walk: a new object 1 (floor gold) owned by the neutral global `0x006F2548` on the start tile at one of eight points, drawn with `0x005558D0(8)` from the table at `0x006A2FA0`: (0x3FF,0xBFF), (0x7FF,0xBFF), (0xBFF,0xBFF), (0x3FF,0x7FF), (0x3FF,0x3FF), (0x7FF,0x3FF), (0xBFF,0x3FF), (0xBFF,0x7FF), i.e. the third-of-a-tile cells 6, 7, 8, 3, 0, 1, 2, 5. It is created, not merged, so each overflowing deposit leaves its own pile. Callers include state 5 (`0x0049F730`), state 29 (`0x00466AC0`) and the store sweep. Built whole as `GoldStore.DepositFrom` (ADR-0355), the room effect as a view request; whether the effect draws on the world stream is not modelled.

Read 2026-10-01 (decompile). `this` is the room; arguments the start tile and the amount. A ruined room (`+0x9A` bit 0) returns at once. From the start tile it follows the tiles' chain links (tile `+0x4`, wrapping to the room's first slab `+0x2D`) until the amount is gone or the walk is back at the start. On a Heart only the tiles `0x004DA1B0` admits (the rim) are filled.

Per tile: the store pile (object 3 of the room's owner) is found or created (`0x004B7A90(3, …)`); its cap is `0x006F25A8` (Heart tile, 1000) for a live Heart, else `0x006F25A4` (3000). A pile it creates is followed by the room's effect when `+0x19`→`+0x425` is set, then `0x005558D0(0x800)` on the world stream (line `0x14F`), which sets the pile's `+0xF4` and `+0x102` (its rotation, LIKELY). Below the cap it takes what fits: the pile (`Object_AddGold`), the room's total `+0x49`, the player's gold (`Player_ChangeGold`) all rise by it.

Leftover after the walk: a new object 1 (floor gold) owned by the neutral global `0x006F2548` on the start tile at one of eight points, drawn with `0x005558D0(8)` from the table at `0x006A2FA0`: (0x3FF,0xBFF), (0x7FF,0xBFF), (0xBFF,0xBFF), (0x3FF,0x7FF), (0x3FF,0x3FF), (0x7FF,0x3FF), (0xBFF,0x3FF), (0xBFF,0x7FF), i.e. the third-of-a-tile cells 6, 7, 8, 3, 0, 1, 2, 5. Its callers include state 29 (`0x00466AC0`) and the store sweep. Built whole as `GoldStore.DepositFrom` (ADR-0355): each new store pile draws rand(0x800) (`GoldStore.PutOn`), the leftover is a new pile at a drawn point; state 29 and the store sweep call it. Not modelled: the room effect (`+0x425`) and whether it draws.

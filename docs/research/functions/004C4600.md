It takes a message type, a player, a variant selector and an allocate flag, and has 151 call sites (message-table.md §4). Type rows come from the 100 x 10-byte table at 0x006A0B00 (low 13 flag bits are lifetime in seconds, 0x2000 NeedsTab, 0x4000 duplicates allowed, 0x8000 variant list). It refuses recipients with non-zero player status, honours world +0x72A1 bit 1 (except types 14/21/48/49), checks per-player suppression via 0x004C5530, returns an unexpired same-recipient same-type record unchanged when duplicates are off, and when the queue at world +0x2E54 is full evicts the oldest record of any player (computer-keeper-messages.md §1). Callers include combat (type 6), heart damage (type 1), rebellion (type 19), portal arrivals (0x0D/0x0E) and the unpaid-training message 0x37. PlayerMessageQueue.Post implements the supported message kinds, including mood and tutorial messages; current coverage and remaining suppression fields are in computer-keeper-messages.md section 4. A subtype row is matched against Data1 and sets the stored subtype (+0x07), string and lifetime; an unmatched one takes the terminator row: string 0 frees the record after any eviction (41, 43), a nonzero string keeps it with timeout 0 (42).

Type 19 (row 0x006A0BBE): flags 0x6032, 50 s, no variant list; reference -10506, Speech.str 506 "Your creatures are rebelling!", raised by state 271's defection at 0x00475156.

Type 0x15, trigger speech (read 2026-10-04, Q227). Data1 is the speech id and is played through `0x00568390` when the recipient is the local player. An allocate of 0 makes no queue record but still plays the speech. Trigger action 24 passes allocate = (low byte of its second dword == 0). All the early returns above come first.

Its speech jump table at 0x004C4AC0 (type - 0xE) sends 0x15 to 0x004C49B4 (read 2026-10-17): the queue id is Data1 as given, the second value world +0x7209, and the subtitle flag 1, so every scripted line queues a subtitle (camera-paths.md §7). Type 0xE's case 0x004C492C sets the flag too.

A new record is linked at the queue tail (+0x10), so a head-first walk (+8, next +0x30) is oldest first; it clears +0x2A (interface bits: 4 dismissed, 8 opened; message-tabs.md) and stamps +0x2C with Clock_GetMilliseconds, which drives the tab slide-in.

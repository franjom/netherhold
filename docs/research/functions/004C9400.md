Takes two triangle indices. Either with bit 3 of `+0xC` (solid) set returns false. Otherwise it reads both region ids (`+0xE >> 6`); if either region's in-use byte (`0x6E96C8 + id*3 + 2`) is 1 the answer is `id1 == id2`. If neither is in use it writes the `fill` line to nav.log when logging is on (`[0x6EC9E8]`, dead in the shipped game), re-runs the fill 0x004C91A0 from the first triangle and returns whether the two `+0xE` words agree above bit 6.

It knows nothing of tiles or corners: the corner-only refusal (Q28, ADR-0339) is the fill's, whose breadth-first walk crosses only a triangle's three neighbour words; read as edge neighbours (STRONGLY INFERRED: the flip and the search use the same words, no corner-only pair has been checked in a mesh dump), two floors that touch at one vertex never share an id. Its one caller is `0x004D0320` (navigation-mesh-and-search.md §5). Ours keeps no region ids: a failed mesh search stands in for the pre-check (ADR-0157), and `GridPathfinder` refuses the same gap since ADR-0339.

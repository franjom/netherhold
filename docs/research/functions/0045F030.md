DK2's own name for it is `spFighting`, printed in its own assertions; it is registered as state 200's handler at `0x0047F027` and state 199's handler `0x0045EB20` tail-calls it (combat-entry.md §1-§2). With no target at `creature+0x502` it calls the acquirer `SelectAVictim` `0x0045CB00`; it then checks target validity, runs the fear checks (escape test `0x00460C50`, withdraw `0x0045EDA0`, counter `0x0045EC80`, flee to state 203), requests the approach `0x00471D10` and switches on AttackType to start action 16 or 17 (combat-fight-state.md §2). It is one of two readers of variable 211 `BackOffMinimumDurationSeconds`, which ships as zero (balance-variables-in-the-binary.md, "Ten are switched off"). STRONGLY INFERRED (binary) in both combat docs; built by ADR-0164 with fear from ADR-0165, the room notice and player event 6 not built.


Steering body bits (STRONGLY INFERRED, reviewer re-read 2026-11-12; body `+0x10E` bit 7 is `is_blocker`, `+0x10F` bit 0 is `ignore_blocker`, the same bytes as creature `+0x232` and `+0x233`): the entry clears both on every path (`0x0045F0CB..0x0045F0F0`); with a live target and no action running, the return after the busy test sets bit 7 and clears ignore (`0x0045F667..0x0045F68F`), before the Support re-acquire; out of reach with no action running clears both (`0x0045F861`, `0x0045F875`); a successful withdraw writes ignore_blocker = owner is not Good (`0x0045F3D6..0x0045F409`). Built in `CombatSystem.Fight` and `FearRules.WithdrawnBody` (ADR-0756), so a fighter at its post is not pushed by Separation (combat-fight-state.md section 2).

Focused46F check: creature+0x46F bit0 clear and forced-target+0x3E6 bit2 clear returns0; later selection branches also distinguish normal bit0 from forced mode. Existing FightRules does not carry that independent physical gate.

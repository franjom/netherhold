Read through 0x004435E0; the room wall chooser and the plain-terrain builder draw such a tile as wall. Bit 15 is neither open nor closed: 0x004488A0 writes it from its record's flag (EDX, loaded from the stack slot at 0x00448945 and unchanged on both arms to the push at 0x004489E7), which that function forces to zero when the record's player is the viewer. So the bit is set for a viewer the door is hidden from and never for its owner. Ours derives it as the tile's secret-door marker and a door owner other than the viewer (`WorldView.IsHiddenSecretDoor`); every sender of the flag was then read (2026-11-26, a second reader): Seven sites post command 0x11, each a flag and the marker write together: Imp state 37 (0x004675F2, flag 1, marker 1 at 0x00467604), Imp state 39 (0x00467869, flag 0, marker cleared at 0x0046781D), the reveal arm of 0x004A55F0 (0x004A6604, 0, 0), the door cleanup 0x004A5290 (0x004A543B, 0, 0), the door sale 0x004C3670 (0x004C37D4, 0, 0), the level-start door sweep of 0x0050B5B0 (0x0050BA02, 1, 1) and the door loader 0x00520F40 (0x005210F6, flag 1, with the marker left to the sweep). So the bit equals the marker for a viewer who is not the owner on every path of a running level.

Where the two can part, none of it modelled: after a saved game is restored the level-start sweep is skipped (0x0050B895 jumps past it) and nothing found rebuilds the bit, while the marker comes back with the tiles (the reader 0x0050ADE0 is unread; the owner saw the door drawn after a load, 2026-11-26); an authored Secret Door whose owner is not in the player chain gets the flag from the loader and no marker from the sweep; and the bit is fixed for the viewer at the moment of the post, with no rebuild if the viewer changed. A Secret Door completed by a crate landing on its blueprint (0x0049F45B) or by the complete-every-door game action (0x00505D00) gets neither flag nor marker, so it is never hidden; ours marks only at the loader and Imp state 37, as DK2 does.

Suspected DK2 defect: DK2-051. After a saved game is loaded, a Secret Door nobody has uncovered is drawn as a door for a non-owner. Two things combine (independent reviewer, 2026-11-26, STRONGLY INFERRED): the presentation grid is not saved, and the map reader's CMap_Load posts command 1, whose allocator 0x00443390 zeroes every cell, so bit 15 is 0; and the post-load fixup 0x004A55B0 calls 0x004A6B70, whose built-door branch (0x004A6DA5..0x004A6DB4) forces the door's draw bit +0xF3 to 1 with no Secret test. Nothing re-posts command 0x11: the level-start sweep is skipped (0x0050B895) and the door loader does not run. The marker itself is saved with the tile (0x00452B90 writes tile bytes +2..+0xB, 0x00452BD0 reads them back) and the door's navigation byte is rebuilt from it by 0x004A55B0, so routing, the Imps' task and the hover are unaffected. Owner observation, level Q888SecretDoors, 2026-11-26. The tile marker survives: after the load the door's tile still hovers as "Enemy Wall" (the hover producers read the marker), with the Secret Door drawn there (SHOT0027). So only the drawing is lost. Ours draws the wall after a load too, by the owner's choice (ADR-0823).

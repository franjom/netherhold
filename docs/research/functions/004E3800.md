It indexes the per-room-type handler table at 0x006a1e9f (base + typeId x 41, guarded 0 < id <= 26) at 0x004E3993 and loads slot +0x01, the type's own constructor, which for a Portal or Hero Portal is 0x004DBB90 (zeroing the generation tally). The table, its ten slots and all twelve indexing sites are marked CONFIRMED in portals-room-handler-table.md; DECISIONS.md ADR-0086 amendment 1 names this function as the constructor that calls slot +0x01. Not mirrored as one routine in src/: our rooms are derived from tiles rather than constructed.

It writes the game turn to room+0x9F (0x004E3965), the size-change stamp. The list link is at the head: the new room's next (+0x08) takes the owner's list head (player +0x36), the old head's previous (+0x06) takes the new room, and the head becomes the new room, so an owner's room list runs newest first; the attack planner's room walks depend on it.

Its only caller is the room allocator 0x004EC490. Among the fields it zeroes are CentrePos (+0x27/+0x29, at 0x004E389A) and the whole type overlay +0x49..+0x66 (seven dwords and a word), before slot +0x01 runs. Every room, including each piece Room_RemoveTile rebuilds, therefore starts its overlay at zero (2026-10-04).

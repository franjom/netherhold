Read whole. When the line differs from the last (+0x410E), it measures the text against the box (+0x40EA wide, +0x40EE high), using the 0x00553A90 resolve and the 0x0062CD80 layout.
- **If the line fits:** it is laid out once through 0x0042CB60 with flags 0x44 and clear 1.
- **If it overflows:** the scroll starts at now + 8000 ms (0x006CE8FC), with the overflow held in 0x006CE900. Each call then lays the line out with flags 0x14 at y offset -min((now - start) / 200, overflow).

The buffer +0x3E73 is then drawn at (0, h - (h >> 3)) by 0x0042CEE0. What the flag values mean on screen is unread (0x0042CB60), hence LIKELY.

The text comes from the level's own string table, not Speech.str: 0x00553A90 reads only 0x00741554, which 0x00553780 loads.

The style is copied from 0x00741320 (0x0062C2D0). 0x005534D0 gives that style the base-10 font, so at 640 wide the subtitle is in FONT_INGAME10 (0x00553690). This is STRONGLY INFERRED, because 0x0062C470 and 0x0062C2D0 are unread (Q608).

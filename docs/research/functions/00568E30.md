It is the reader before the definition builder 0x00492320: it copies file fields into the staging record, which the builder then packs into the compact definition creatures point to. Two reads pin the +0x3F0 mapping against instructions: the four 2-byte resistance pairs from file +0xE0C into record +0x11FC (at 0x0056983E), and the base-type bytes record +0xD3B and +0xF4B, which land in staging +0x112B and +0x133B before the builder moves them to def+0x5B3 and def+0x770. Both docs read it from the binary, but neither marks it CONFIRMED, hence LIKELY. Our KwdCreatures parser reads the same file fields at their file offsets.

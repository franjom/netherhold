Its only caller is the per-tick creature update 0x00488930 (at `+0x1138`), which also calls the state dispatcher 0x00476FC0, so the action handler runs once a tick (training.md §6.2, CONFIRMED).

Read 2026-10-01 by disassembly. It does not call 0x00496DC0: it indexes the action table inline. The action id is `creature+0x3A9`; id 0 or 21 (`0x15`) is no action. The record is at `0x006E4198 + id × 0x1D` (29 bytes): `+0x00` the handler, `+0x04` the `this` offset added to the creature, `+0x14` a flag byte, `+0x15` the mode dword, `+0x1B` a duration byte compared with now (`0x00517490`) less the stamp `+0x3A5`. Mode 3 calls the handler once (until `+0x3AD` bit 0 is set) and then holds while the animation runs (`+0xDC`), which is mining-cadence.md §5's one action, one application. When the action ends it clears the block `+0x38D`–`+0x3AE` whole (creature-action-table.md §2).

Read whole by decompilation and the mode-3 instruction window. The null-handler mode-3 records used by actions 53/64 mark their handler work complete immediately and hold until creature+0xDC is zero (0x00496B6D), together with the cycle-completion flags. This field is the normalized advance rate at animationObject+0x98, with animationObject = creature+0x44. It is a scalar, not an instance pointer.

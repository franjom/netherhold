Its only caller is the per-tick creature update 0x00488930 (at `+0x1138`), which also calls the state dispatcher 0x00476FC0. The nine work actions (ids 1, 2, 4, 5, 7, 8, 10, 11, 12) are mode 3, written at record `+0x15` by 0x004950C0. Handler completion determines whether subsequent polls call it again; mode 3 alone does not guarantee one call per action.

It indexes the action table inline rather than calling 0x00496DC0. The action id is `creature+0x3A9`; id 0 or 21 (`0x15`) means no action. The 29-byte record is at `0x006E4198 + id × 0x1D`: `+0x00` the handler, `+0x04` its `this` offset, `+0x14` a flag byte, `+0x15` the mode dword, and `+0x1B` a duration byte compared with now (`0x00517490`) less start stamp `+0x3A5`. Mode 3 polls its handler until completion bit 0 is set, then waits for animation completion. Ending an action clears the whole block `+0x38D`–`+0x3AE` (creature-action-table.md §2).

Read whole by decompilation and the mode-3 instruction window. The null-handler mode-3 records used by actions 53/64 mark their handler work complete immediately and hold until creature+0xDC is zero (0x00496B6D), together with the cycle-completion flags. This field is the normalized advance rate at animationObject+0x98, with animationObject = creature+0x44. It is a scalar, not an instance pointer.

For ordinary recovery timing, the same creature turn polls this runner
before its state handler and later advances animation; see 0x00488930 and
0x0048BE50. Completion installed by that advance is observed at the next
turn's poll. An initially zero rate likewise completes at the next poll.
The exact turn mapping is in keeper-spell-tremor.md's Animation clock.

The mode-0 null-handler arm (action 55, the victory pause): with a zero art byte at record +0x14 it keeps the action; otherwise a zero +0xDC clears the block; a cycle flag (+0xF1 & 6) with count byte 0 also ends it, a count above 1 decrements, and a count of 1 with flag bit 1 sets 0xFF. Started with count byte 2 by 0x00496A30, action 55 ends only on the zero rate, the same turn a null mode-3 record would (Q376).

Re-decompiled 2026-10-12 for the possessed dig/claim actions. The "once per action" above is the handler's choice, not the runner's: in mode 3, while +0x3AD bit 0 is clear the handler is called every poll, and bit 0 is set only when it returns 0. The dig, mine and attack-floor handlers (actions 1, 2, 5) return 0 right after a strike that leaves the tile workable, so they strike once per action; the claim handler 0x004974C0 returns 1 while the tile is still claimable, so it strikes again every poll until the tile converts. Bit 1 (completion) needs a nonzero record +0x14 and then a zero +0xDC or a cycle flag (+0xF1 & 6) with count byte 0. Mode 0 with a handler and duration byte 0: the handler is called each poll and the block is cleared on the first poll it returns 0 (action 6's 0x004977F0 always does, so it lasts one poll). A nonzero duration byte calls the handler each poll while now − +0x3A5 ≤ duration, and clears the block after.

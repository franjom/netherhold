Thiscall on the runtime map; stack arguments (x, y, player, creature type), RET 0x10. Read whole in disassembly 0x00450910..0x00450BDB. Returns 0 at once when x >= width (+0x0C) or y >= height (+0x10), when the navigation grid (+0x18) byte has bit 3 set (solid, the bit World_TileNavigationSolid 0x00509200 reads), or when Map_TileIsDoor 0x004528E0(x, y, 0) finds a door. The definition comes from map +0x08 slot +0xC0(type); "allied" below is Tile_OwnerPlayer 0x00455990 of the cell asked Player_IsAllied 0x004BF3D0(player), which is true for the player itself, and "neutral" is the tile owner (+0x08 & 0xFFF) equal to [0x006F2548].

**Worker (definition +0x686 bit 0, IsWorker):**
1. A Combat Pit (16) tile that Room_IsFloorSlot 0x00454110 accepts: 0.
2. A Dungeon Heart (5) tile not owned by the player: 0 unless 0x004DA150 returns 1 (the tile is off the Heart's inner 3x3).
3. IsEvil (+0x686 bit 7): 0 on a Portal (3) or Hero Portal (25) tile whose cell byte +0x0C is 4. Without IsEvil: on any Heart tile, 0 unless 0x004DA150 returns 1.
4. A Prison (11) floor slot (0x00454110) for an IsEvil worker: 0.
5. Allied and not neutral: 1.
6. Neutral, terrain flags +0x17B (table 0x006DA4A8 by cell byte +0x0A) with neither 0x80 (water) nor 0x100 (lava), and no room (word +0x02 & 0xFFF == 0): 1.
7. Otherwise 0.

**Non-worker:** 0 unless allied and not neutral. Then the result starts at 1 and:
- a Combat Pit floor slot: 0x004D8430 (CombatPit_DropTest, a free floor slot) when the tile owner is the player, else 0;
- a Heart tile: replaced by 0x004DA150 (1 off the inner 3x3, 0 on it);
- a Portal (3) tile with cell byte +0x0C == 4 owned by someone other than the player: 0.

The decompiler shows the alliance calls with wrong arguments; the order above is from the instructions (0x00450A77..0x00450A88, 0x00450AF9..0x00450B26).

Decompiled 2026-10-06. Arguments: from x/y, to x/y, the corridor, its gate count, the output block, and an option. It first runs 0x004CEF40, the pass that turns the corridor into path points and returns their count, and copies from/to into the block. With a gate count of zero it stores the destination as the single record (both points of +0x10..+0x1C the target, +0x28 zero) and sets the count at +0x1C10 to 1. With gates it runs the cross-product funnel tests per gate (logging 'Exceeded max path length' when the record count reaches 0x100; it does not stop writing), then appends the destination and stores records + 1. So a successful route always ends at the destination and has at least one point; DK2 has no 'already on the target's tile' shortcut anywhere on this path. Ours: WorldSteering.TryRouteToStance loads the one point on the same tile; the fight approach uses it since ADR-0388, while TryRouteTo still gives other callers a finished route (Q565). The funnel arithmetic is ours in GateWalk.cs and is not compared here.

Whole decompile with scoped assembly windows read. Calls0x0048DEA0 and0x004BE090 in conversion branches. The full semantic classification and conversion behavior remain unsettled. Arm 0x14 (action 20) is built (ADR-0495); the rest is not attributed.

Arm 0x14 (action 20, read 2026-10-16): Object_Create_LIKELY(0x1C, owner +0x28, position +0x1A); on success Creature_PickUpCarriedThing 0x0048B350 with the new thing (refused when +0x3C3 is nonzero) and +0x92 |= 4 either way; on failure (0x0049AD92 JZ 0x0049B138) nothing is set. Both paths return 1.

It is the creature-level trigger action dispatcher (trigger-walkers.md: base 15, range 0x1C; its default calls the player dispatcher 0x004C8620). The possession calls above are inside its action arms. Case 0x23 (action 35, read 2026-10-04, Q227) reads byte 00:
- 0 clears `+0x3E6` bit 0x20 (no corpse) and sets 0x40 (no gold spill), then slot `+0x20` (`0x004B2AD0`) zeroes health so the entity pass removes the creature that turn.
- 1 calls `Creature_EnterDeathFall` `0x00459560`.
- Anything else does nothing and returns 1.

A definition flagged 0x4000 (IsHorny) takes a separate routine (the Horny branch below); three states return at once and two take a short path. The LastSlapTick window (creature+0x4BB plus variable 19) guards only the knock-back impulse, so there is no cooldown on the slap itself; then it writes LastSlapTick, applies the anger branch described in [casino-winner-slap.md](../casino-winner-slap.md) (ordinary AngerSlap unless the unpaid jackpot deadline is nonzero), raises speed to 150 % if SpeedChangeTimer is zero, and sets WorkFasterTimer to a hardcoded 100 ticks (25 s), which is why slaps do not stack. Its one SetState, the shared tail at 0x0048BA06, takes its state by the creature's room (+0x3B9), read 2026-10-01: in a room the slapper owns, type 10 sets 67 (0x0048B9DB), type 11, a Prison, sets 120 (0x0048B9C3), type 12 takes damage and returns, any other type sets 77; in another keeper's room it sets nothing and skips the events; with no room, states 0x43, 0x78, 0x84 and 0xC5 return without any effect (byte table 0x0048BD9C, entries 0x0048BD88), and the rest set 77. It is the only entry to 77. It fires creature event 5 and player event 0x3C, and stamps the research slap window. The handler order is a binary read; the ten-point, non-stacking, 25-second bonus is owner-confirmed, the no-cooldown reading is STRONGLY INFERRED (hand-of-evil.md summary). SlapCreatureCommand mirrors it without the knock-back; the state change is SlapRules.Move (ADR-0401).

`NumberOfSlaps` (read 2026-10-04, Q278): both counting sites add 1 to `[creature+0x2A]+0xEE6`, the slapped creature's owner. The second argument, a player record, gives only the damage source's `TagId`.
- States `0xD1`/`0xFF` count, fire the events and return early.
- The main path counts after the SetState tail.
- No count: `IsHorny`, states `0x4C`/`0x65`/`0xC1`, a held room (`+0x3B9`) the slapper does not own, with no held room states `0x43`/`0x78`/`0x84`/`0xC5`, a refused SetState, room type 12 (damage only).
- Every no-count path but type 12 returns before the damage, anger and bonus too.

The two event sites (disassembly and decompile re-read 2026-11-11, STRONGLY INFERRED). Each is `0x0049AA30(slapped creature, 5, 0, 0)` followed by `0x004C7A50(creature+0x2A, 0x3C, 0, 0)`, so player event 60 goes to the slapped creature's OWNER, not the slapper.
- Main path: site 0x0048BCB2, after the damage call 0x004B2CE0 (0x0048BBBC), the speed block, the slap effect and the `+0xEE6` count (0x0048BCAA). Nothing follows but the return.
- Short path, states 209 and 255: site 0x0048BD08, after the `+0x4BB` stamp and the damage call (0x0048BCFB), before the slap effect, 0x004813C0 and the `+0xEE6` count (0x0048BD77). No speed block on this path.
The damage-only type-12 arm and every refused arm fire nothing. No other event site is in the function, and no death test comes before the two events.

Main path: damage 0x0048BBBC, the speed block (0x0048BBC1-0x0048BC42), `+0x4D7` = 100, the slap effect, the count 0x0048BCAA, then the events 0x0048BCB2 and 0x0048BCC0. Ours fires both from `HandSystem.Slap` for the Full and Short outcomes (ADR-0770): Full after the owner's SlapCount, Short before it, the Dismissed and damage-only outcomes nothing.

Built in HandSystem.Slap with these arms on HeldPlace (ADR-0373). The main path makes the state move through SlapRules.Move (ADR-0401), and a refused move ends the slap with nothing counted or applied, as at 0x0048BA0B. The Horny branch is built (ADR-0776).

The Horny branch (read 2026-11-13, STRONGLY INFERRED). IsHorny is tested first (0x0048B8B1). On a Horny, 0x0048B8BC..0x0048B916 runs the same sequence as the Reaper's countdown end (0x004889AB..0x00488A00): state 242 through 0x00476D30, +0x46F bits 0 and 3 cleared (0x0048DF10(0), 0x0048DFA0(0)), the move stopped (0x004D1070), velocity zeroed. Then it returns: no slap tick, damage, anger, bonus, events, count or sound. Ours: HandRules.CanSlap admits a Horny while ReaperCanAcquireFight (+0x46F bit 0) is set and its state is not 76; HandSystem.OutcomeOf returns SlapOutcome.Dismissed; HandSystem.Slap calls ReaperRules.Depart and emits slap_dismissed. The function's only caller is the slap effect's start callback 0x004C0F80, reached from the slap action 0x00513690 for the human hand and the computer keeper alike, so 0x004918B0 gates only the human hand's UI.

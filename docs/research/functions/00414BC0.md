No code calls it: its only reference is a pointer at `.data 0x006911E0`, so it is an interface draw callback. It fetches the viewing player through the world's vtable slot 0x260 and draws `player+0x7E` (Money) in gold. Before drawing it compares the turns left until payday (0x004BE180, `player+0xB53` minus now) with `PayDayCutOffTimeSeconds` at `0x006F28A3` (100 if that is zero). Below it, or while a latch at `this+0x13FD` is set and the last payday (`player+0xB4F`) began less than ten game seconds ago, it sets the latch and, on alternate 500 ms real-time phases, shows minus the wage bill instead of Money. The bill is 0x004BE290, the level-scaled Pay of every payable creature without `GetPaid`, kept at `this+0x13F5`. During bill phases it refreshes only when the current millisecond clock exceeds the cached stamp at `this+0x13F9`, then stores that clock unchanged. It is red when Money is below the bill, blue otherwise. The rest of the body draws the panel's frame through the renderer (vtable slot 0x5C). Odd 250 ms phases while FlashButton action9 targets general category0/buttonF3 skip the counter before reading the player or updating the payday latch.

The comparison is against raw turns: the setter stub at 0x0051CF9F stores the level value unchanged, so 120 is 30 game seconds, not 120. Whole body read. The resource-menu21 widget6911A8 confirms the callback binding; exact drawing facts are in hud-resources.md.

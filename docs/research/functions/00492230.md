Read 2026-10-01 by disassembly. It opens an SEH frame (`FS:[0]`, handler `0x0064B57E`) and calls the vector-destructor iterator `0x00635DA0(array, size, count, 0x00401200)` on the definition's member arrays one after another (`+0x65E` 5 × 3, `+0x64A` 6 × 3, `+0x63C` 6 × 2, …), stepping the EH state down between them. It stores nothing into the definition. So it is not a serializer: combat.md §6.1.1's "(0x61C, element size 2, count 4)" is one of these iterator calls on the resistance slots, a teardown, not a write. The conclusion there stands (no damage path reads resistances, Q335). Reported as the pair of the constructor `0x00491DC0` (not checked here).

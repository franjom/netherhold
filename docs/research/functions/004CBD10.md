Read only far enough to confirm, with its helper 0x004CBBD0, that neither stores a constraint bit (+0xD bits 3..5) directly; the flip 0x004C9FC0 they call does move bits, but only between edges that already carry them. That supports the whole-map build carrying none (ADR-0461): the reset 0x004C8D10 clears them, and the only setter the research found is the partial rebuild's side marker 0x004CE380 (navigation-partial-rebuild.md §2.2), so a whole-map build's edges are all flippable and only a partial rebuild's side marks refuse flips. Turns the fan with 0x004C9540. How it chooses the crossing edges and the flip order was not read; ours (`NavMesh.InsertConstraint`) uses the Sloan crossing-edge sweep (ADR-0157), a known residual against the original's order.

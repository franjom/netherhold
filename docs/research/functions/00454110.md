It checks that the cell belongs to a room and that map byte +0x0C is 0xFF (interior), then branches on room type through a 20-entry table at 0x0045421C. workshop-crates.md section 4 (and room-slab-chain.md, combat-pit.md, ADR-0190) read it as "accepts": never for types 3, 5, 8, 0x11, 0x16; on one checkerboard parity (x + y + room+0x80) for Guard Room, Workshop and Casino; for the Graveyard only without object 75; always for the rest. hero-party-walk.md section 6 describes the same table with "non-zero meaning refused", which swaps the words for every type, so one of the two has the polarity backwards (the room-slab-chain Prison-door and Casino-lever readings, which the owner's screenshot backed in ADR-0190, fit the "accepts" reading). binary-entrance.md section 4 says Prison and Combat Pit land on an arm that returns 1 unconditionally, with the +0x0C guard unread, and AttractionBudget.cs counts every slab of those rooms on that basis; room-slab-chain.md section 5 and combat-pit-spectators.md say a Prison or pit rim fails the test, so the budget may overcount. Ours computes the slots in AutoFurnitureRules (FloorSlots) and uses the test in CrateRules, StealGoldRules, HeroJobRules and the imp wander.

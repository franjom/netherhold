Read from the binary on 2026-09-30. The function first requires the cell to belong to a room (word +0x02 & 0xFFF non-zero) and map byte +0x0C to be 0xFF (interior); a cell failing either returns 0 before any room-type logic, for every room type. Only then does it index a 20-entry byte table at 0x0045421C by room type minus 3 into a 10-entry jump table at 0x004541F4. Result per room type: 0 (refused) for 3 Portal, 5 Dungeon Heart, 8 Wooden Bridge, 17 Stone Bridge and 22 Hero Stone Bridge; a checkerboard parity test (cell x + cell y + room+0x80, accepted when even) for 9 Guard Room, 10 Workshop and 15 Casino; for 14 Graveyard, refused on the one cell holding object 75, else accepted; 1 (accepted) for every other type, including 11 Prison and 16 Combat Pit, and for types outside 3 to 22. So a return of 1 means accepted, as workshop-crates.md section 4, room-slab-chain.md, ADR-0190 and (since 2026-09-30) hero-party-walk.md section 6 state. A Prison or Combat Pit therefore contributes its interior cell count to attraction (binary-entrance.md section 4, ADR-0147 amended; AttractionBudget.Contribution uses InteriorTileIndices.Count since 2026-09-30).

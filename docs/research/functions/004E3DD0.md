A thiscall on the room. It calls `0x004EF6C0` with `ECX = [0x006ED484] + 0x9BE` (the world's room manager) and the room as argument; that walks the slab chain from `room+0x2D`/`+0x2E` and calls `0x004EDC10` on each slab, which dispatches on a byte of the room's definition (`+0x452`, 1 to 13). Then it indexes the handler table at 0x006A1E9F by `room+0x18` (0 < id <= 26) at `0x004E3E00` and calls slot +0x11 on the room when it is not null. Its only caller, `0x004EC410`, walks the room manager's room list (head `+0xE`, next `room+0x21`), and that has one caller, `0x0050B3C0`, the world rebuild run by the file restore `0x0050E920`, so this runs only when a saved game is restored. Reading the table for all 26 types, slot +0x11 is null for all but three: the Library's (6) is `0x004E10D0`, the same function as its +0x09 tile pass, and the Lair's and Workshop's are the empty `0x00401200`. LIKELY rather than CONFIRMED because that the restore path is a saved game rests on the file-open and world-reset shape of `0x0050E920`, not on a read of its deserialiser.

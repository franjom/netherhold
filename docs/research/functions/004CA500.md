Arguments (t, x, y). Allocates triangle A then B: each from the head of the list at 0x006A11D4 (link in the slot's +6 word) when it is not -1, else the high-water mark 0x006ECA2C, bumped; the live count 0x006ECA30 rises; each gets +0xC = 0 then a 16-byte copy of t. The point p is popped from 0x006A11D8 (link in the x word) or taken from the high-water mark 0x006ECA34; its coordinates are written. Vertices: t's slot 2 := p, A's slot 0 := p, B's slot 1 := p, so t = (v0, v1, p), A = (p, v1, v2), B = (v0, p, v2). Neighbours: t's slots 1, 2 := A, B; A's slot 0 := t, slot 2 := B; B's slot 0 := t, slot 1 := A. Flags +0xD: t |= 6 and &= 0xF; A |= 5 and &= 0x17; B |= 3 and &= 0x27, which sets the edge bits of the new inner edges and clears their constraint bits while keeping each inherited outer edge's. The outer neighbours across A's slot 1 and B's slot 2 have their back links repointed from t. t's region id (+0xE >> 6), when set, has its record's count decremented and in-use byte (+2) zeroed, +0xE masked to 0x3F and record 0's count incremented (0x004CA7B4..0x004CA7DD); A's and B's +0xE are zeroed; width classes are recomputed for all three. The allocation order, triangles before the point, is what fixes slot reuse after a removal.

The minimap's per-tile colour class (a WORD stored by `0x00451C60`). Full body, in order:

1. A virtual call through the view interface (`[[[this+8]+4]+0x10]` slot `+0xD4`, args x,y) returning non-zero gives **`0x0D`** before any fog test. This is not the direct World vtable. The slot's target is unread; calling `0x0D` the drag-highlight class is an inference (OpenKeeper uses it that way), not a reading.
2. **Fog:** returns **`1`** (unknown; drawn as rock) unless the explored bit (`tile+9` bit `0x20`, i.e. `+8` word bit `0x2000`) is set, or the scanned bit (`+0xB` bit `0x40`) is set on terrain with flag `0x01000000` (`RevealThroughFogOfWar`) (fog-reveal-sources.md §1).
3. Only after that: a Dungeon Heart cell (`0x00453A20` with the tile as `this` and 5 pushed, `Cell_IsRoomOfType`) gives **`0x23 + owner.Number`** (`+0x10FC`). The Heart test is on the *visible* side of the fog test, so a fogged Heart is not drawn.
4. Owner (`tile+8 & 0xFFF`) not equal to `DAT_006F2548`: **`0x11 + Number`** when a byte in a second grid (`[this+0x18]`, stride `+8`, base `+0x10`) has bit `0x08`, else **`0x1A + Number`**.
5. Else a room on the cell (`tile+2 & 0xFFF` non-zero): **`0x1A + Number`** of `Tile_OwnerPlayer`.
6. Else by the terrain record (`DAT_006DA4A8[tile+0xA]`), flags at `+0x17B`: bit `0x01` with a non-zero word at `+0x185` gives **`5`** if flag bit `0x02` is set, else **`7`**; bit `0x01` without it gives **`4`** when `Tile_IsDiggableWall` (`0x00453D10`) is true, else **`1`**; bit `0x80` gives **`9`**; bit `0x100` gives **`0x0B`**; otherwise **`2`** if byte `+0x1CB` bit `0x01` is set, else **`0`**.

Every return is a direct `RET 8`. The callees `0x00453A20`, `0x00453D10` and slot `+0xD4` are not read here, hence LIKELY. Q197 still stands: no room type, the Portal included, is drawn through fog by this routine. Fog itself is built (FogOfWarSystem); this renderer routine is not mirrored. OpenKeeper's 2026-10 minimap (`MapColourClassifier`, commit range 1d9a1c71..4f2ab401) reproduces this table's structure and order, with two substitutions of its own: an impenetrable flag in place of `Tile_IsDiggableWall` for the 1/4 split, and a health-based "claimable floor" heuristic in place of the `+0x1CB` bit for the 2/0 split.

Read as assembly 0x0058AF70-0x0058B185. It is the target of 0x0058ACB0 (Vertex_ProjectThroughTemporaryTransform), chosen with TriSink_Clipping when Renderer_SelectVertexSinks gets a zero sixth argument, and of 0x0058AD70 (stored at 0x0077F92C in both arms). Outcode bits: bit 0 y < -z, bit 1 y > z, bit 2 x < -z, bit 3 x > z (from the signs of z+y, z-y, z+x, z-x); a non-zero outcode skips the projection and is stored at slot +0x1C of table 0x0076F358. So the clip volume is exactly the viewport frustum, with no guard band; any vertex with z < 0 has a non-zero outcode (z+x and z-x sum to 2z). The fade block (frame flag bit 3) ORs 0x20 into the outcode when t < 0; TriSink_Clipping then drops a triangle whose three vertices share any outcode bit. Otherwise as 0x0058ADC0 (the depth branch operands were read there; the same two branches appear here, register order not re-derived); see possession-warp.md section 2 and 4.

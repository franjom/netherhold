A thiscall on the 5449-byte creature record taking one stack argument (RET 4). For i below 4 it returns the byte at record `+0x11FC + 2i`, otherwise 0. Its one caller is the definition builder (`CreatureDef_BuildFromRecord`, `0x004936A9`), whose loop at `0x0049368E` stores this result at `def+0x61C + 2n` and its sibling `0x00569DB0`'s at `+0x61D + 2n`, for each slot the record's per-slot dword at `+0x284 + 4i` (read by `0x00569D70`) marks present, counting them in `def+0x78A`. That it is the type byte comes from the file layout: record `+0x11FC` is file `+0xE0C`, the first byte of each pair, which KwdCreatures parses as the attack type; the shipped data agrees, the first byte holding small ids and the second percentages (the Salamander's second bytes are 75, 50 and 50). Nothing in src/ mirrors the accessor, and combat.md 6.1.1 finds no damage path reads the packed pairs.

Its one caller is the death block of the health routine 0x004B2CE0, on the arm where def+0x686 bit 23 (CanBeResurrected) is set (call at 0x004B31B0).

The guards, read in full 2026-10-04 (0x0048FFC0-0x00490111), in order:
1. The creature's cell is not an interior Temple cell. 0x00453A20(13) tests the cell's room type, then Room_IsFloorSlot 0x00454110, which needs cell +0x0C == 0xFF. A hit returns.
2. The owner's Graveyard capacity gate 0x004DDCA0, called on creature+0x2A, passes. It fails with no Graveyard.
3. Player_RandomRoomOfType(14) 0x004C6460 finds a Graveyard whose +0x9A bit 0 is clear.
4. The level byte +0x403 is above 1.
5. +0x3EA bit 2 is clear (CantBeResurrected, set by the Monk's blow around the damage call).

Then it moves the creature through 0x004B5560 to that room's CentrePos (+0x27/+0x29) as a tile centre (x << 12 + 0x800). It sets health +0x40 to the level-scaled maximum, calls the level decrement 0x0048AFA0, clears +0x3E6 bit 0x8000 (CombatPitFighter) and sets state 1 (0x00476D30). It returns 0 on every path (0x0049010B), so the caller's health copy after its JZ at 0x004B31B7 never runs.

A failed guard leaves health at 0 or below. That the death then proceeds is STRONGLY INFERRED; the downstream path was not re-read.

Not built: CreatureDeathRules.CanBeResurrected only tests the flag.

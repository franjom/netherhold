Both `Hunger_TryToEat` (0x004633D0, before state 91) and state 91's handler 0x004634B0 call it, so a failure in the needs routine already posts. It walks the player's room list (`player+0x36`) for type 4. A hatchery that `0x00471740` reaches with options `0x80` is a candidate when word `room+0x0C` (ObjectList) is non-zero, kept by unsigned strict-less squared distance (`0x0043C260`) from the creature to its FirstSlab (`+0x2D/+0x2E`) centre, so the first in list order wins a tie; a reached one with an empty ObjectList marks the 42 flag when dword `room+0x51` (ChickensGenerated) is non-zero and the turn minus `room+0x9F` exceeds 4 x ticks-per-second, unsigned (`0x004DEDAB`-`0x004DEDD4`). A candidate is stored and 1 returned. Else, at Hatchery availability 3 (`0x004BAB20(4)`): no hatchery posts 41; else one with a non-empty ObjectList that option 2 cannot reach posts 43; else the flag posts 42. Each branch returns 0 instead while `0x004C7340` or `0x004C7360` reports a pending build or sale. Each posts `0x004C4600(type, creature +0x28, 4, 0, 1)`.

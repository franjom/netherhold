- `0x004655E3` calls `0x00496D00` on the creature: nonzero (an action still running) returns 1, the state holds.
- `0x004655FC` calls `0x00508070(+0x8A, 1)` on the keeper's pool: is the id a live kind-1 entry. Zero runs the leave hook `0x004647D0`, clears `+0x8A` and sets state 10, and nothing is raised.
- Otherwise the tile `+0x8C/+0x90` is tested with `0x00453D10` (diggable): nonzero starts action 1 (`0x00496980(1, ...)`) and stays.
- Not diggable: `0x005081C0(+0x8A)` reads the entry; when its tile is the task tile (`+0x8C/+0x90`, compared as tx<<12, ty<<12 at `0x0046569D`–`0x004656C5`), not where the imp stands, and its byte `+4` (the entry's kind) is 1, `0x00508040(+0x8A)` removes it. Then `+0x8A` = 0 and `0x00476D30(10, 0)`; if that succeeds and the tile passes `0x00453FC0` and `0x00453B30(owner)`, a kind-14 entry on the tile is looked up (`0x00508200`) and raised (`0x00507BB0(14, ...)`) when there is none.

The id test is by id only, so an id freed and reused is alive. Level 1 seed 4 (DK2 capture): imp 455's dig walk dropped task 2 at (10,28) at tick 57, the player's next tag reused id 2 at (15,32), and digger 454 at 58 found it alive, removed nothing (other tile) and raised kind 14 #25.

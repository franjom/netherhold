It takes the requested state id and an out-flag pointer (0 almost everywhere) and reads the current id from the state object's `+0x10`. **Guards come first** (state-category-hooks.md §5): it returns 0, writing nothing, if a state-object pointer at `+0x04`, `+0x08` (the creature) or `+0x0C` is null, or creature `+0x3E6` bit 0 (`InHand`) is set; then it clears the out flag. The rule compares the group tag (`+0x16` of the 25-byte record, equality only) and indexes the category (`+0x17`) into the mask table at `0x00699688 + cat * 0x40`, testing the target's bytes in a fixed order (creature-state-table.md §2.2). travel-states.md §3 reads the walk rows: entering a category-2 walk saves the current id at `+0x40` and runs no hooks; 2 → 2 recurses through SetState(1) first, which the rule also judges and never refuses. Otherwise differing categories (`+0x40`'s when leaving a walk) run the old category's leave hook (its return discarded), write `+0x10 = 1` raw and set the out flag, then run the target's enter hook; **a zero return returns 0 at once, leaving the creature in state 1 with `+0x18`, `+0x1C` and `+0x44` unwritten**. Commit writes `+0x10`, stamps `+0x18` from the turn and zeroes `+0x1C` and `+0x44`; it never writes `+0xDF`. A hook slot is a member pointer (function at `+0`, `this` adjustment at `+4` added to the state object into ECX); a null slot is skipped. `CreatureStateMachine` mirrors steps 2–6 and dispatches through `CategoryHooks` (ADR-0308); the guards are not modelled (Q503). It never touches the action block, so a 199 to 203 move (one category, no hook) leaves a swing running.

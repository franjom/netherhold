The only reader of variables 145 `NumberOfRandomWallDeteriorationsPerSecond` (`0x006F2919`) and 146 `WallDeteriorationDamage` (`0x006F291A`). Both ship at zero and no level overrides them (variables-corpus-sweep.md), so no wall erodes in DK2 as played; ADR-0085 calls it a whole feature switched off, not cut. The reviewer read the body whole in disassembly (2026-11-20, STRONGLY INFERRED).

Count: variable 145 is an unsigned byte; 0 returns before any draw, otherwise at most 255 picks, with no time gate. Its only caller, the keeper frame 0x004BB2A0, calls it at 0x004BB58D every turn (World_TickPlayers 0x004C2310 is ungated): after the mana update 0x004BB586, before 0x004C0AA0 and the refresh-clock draw 0x004BB689, for keepers only, and skipped for a fallen keeper without +0x76 bit 22. So the count is per tick, not per second as the name reads.

Each pick draws x = Random_Next(width + 1) + 1 (0x004BB70F) and then y = Random_Next(height + 1) + 1 (0x004BB73B) from the world seed (Random_Next 0x005558D0, world +0x15A0), both before any test. The bounds test 0x00509090 needs x < width and y < height, so x = 0 never occurs. A pick qualifies when the terrain (+0x17B) has Solid set and Impenetrable clear, the tile owner (tile +8 & 0xFFF) is the keeper, the terrain GoldValue (+0x185) is 0, and Tile_TouchesOwnFloor 0x00453B30 holds: the repair predicate 0x00453E30 without its health test.

Damage: the MOVSX of the byte variable 146 (signed, unscaled) goes through Map_ApplyTileWork 0x004508D0 to Tile_ApplyWork 0x00452F60 with the tile's owner as worker. A negative value damages and a positive one heals; at 0 health the destroyed type (+0x1C6), sound 0xF4 and the destroy effect (+0x1C9) follow, with no breach message because owner and worker are the same. 0x004B9EC0 is Player_Tick, not a damage routine.

Built as WallDeteriorationRules.Run, called from DungeonHeartSystem's keeper tail just before KeeperRefreshClockRules.Advance; SpecialSystem.Work, which mirrors the tile-work chain, is reused (HashVersion 534).

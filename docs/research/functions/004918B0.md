Thiscall on the creature with one argument, the keeper's player id; both its callers are in Hand_HandleSecondary 0x00408EE0 (0x00409229 for an own creature, 0x004092B2 after the pick-up permission 0x0048E6A0 for another keeper's). It returns 0 when any of these holds, else 1:
- the definition's +0x686 bit 2 (CanBeSlapped in our flag enum) is clear;
- the creature's +0x3E6 bit 21 is set (dying);
- the word +0x3CB (the keeper whose prison holds it) is non-zero and not the argument;
- the current state +0x25E is 0x4C (76, the hand's drop, still falling);
- the definition's +0x686 bit 14 (IsHorny) is set and the creature's +0x46F bit 0 is clear.
So a keeper cannot start a slap on a creature that was just dropped and has not landed; the swing, the slap action and every slap effect are skipped. Ours reaches the same outcome later: HandRules.CanSlap has no state test, but HandSystem.OutcomeOf returns Nothing for LandingPending or states 76, 101 and 193 (HandSystem.cs, the slap arm tests), and HandRules.HasPickupPermission refuses 76 and 193 for the cursor's other arm. One difference is not modelled: a Horny is refused outright in ours (CanSlap), where DK2 refuses it only once +0x46F bit 0 is cleared (the Reaper's state-242 countdown clears it, combat-acquisition.md). Whether a Horny with bit 0 set can be slapped in play is read, not observed; Hand_SlapCreature 0x0048B8A0 sends a Horny through its separate routine either way.

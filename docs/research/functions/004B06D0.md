It walks the rectangle inclusively like the type 39 counter 0x004B0620 and ends at the same predicate 0x004B0A80, but it asks for existence, not a count, and adds two filters: a creature needs +0x3E6 bit 7 and an object needs +0x146 bit 3, both Possessed per the debug dumpers. Byte 01 is the player, byte 02 the subtype, byte 03 == 6 selects objects (anything else creatures); no comparison or value is read. The six shipped records all select creatures of player 3. Built from PlayerState.PossessedCreatureId for the creature branch; the object branch declines (no object-possession state, Q280). trigger-semantics.md's line that 39 and 70 are unimplemented with an UNKNOWN filter predates ADR-0115 and the dispatch-tables reading and is stale.

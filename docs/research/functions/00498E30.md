Order (decompiled whole 2026-10-12): +0x3EA bit 12 := def+0x686 bit 29. Gate A unless Possessed (+0x3E6 bit 7): now <= creature+0x3A5 + def+0x5CA - 1 returns 1 and keeps the action. Past it, the target tag +0x399 must name a live slot (0x006ED540[tag] != 0) whose layer dword +0x16 != 2, else return 0 with nothing done. blow = -Combat_MeleeDamage. Target vtable +0x34 must return nonzero (object 0x0066D654, shot 0x0066D86C, body 0x0066D904, door and trap all hold 0x00628BC0, return 1), else return 0. A hit point from world+4->+0x10 vtable +0x10C(attacker, 0, &pt, &out), the target's position when it returns 0.

Class arms, in this order: class 0 (creature): the carried/lair block (0x004E0460, +0x3B7), +0x445 nonzero returns 0, impact from target def+0x685, the def+0x686 bit 14 same-owner kill (target KickToState 0xF2, +0x3E6 bit 5 cleared, vtable +0x20, return 0), the bearing bonus (atan2 & 0x7FF reflected, /20, applied when > 15 as blow += blow*b/100). Class 4 (door): impact from door def+0xB3. Class 3 (trap): impact from trap def+0xBF. Class 2 (object): impact from object def (+0x12D) +0x11C via Attack_LookupImpactPair(def+0x77A, ...). Class 1 (shot) and class 6 (dead body) have no arm: no impact lookup.

Then, when blow != 0: owner byte +0x1090 > 0 -> blow = (c+10)*blow*10/100; owner byte +0x1091 > 0 -> blow = (c*15+100)*blow/100; a Monk attacker (+0x36F == 0x13) on a creature brackets the call with target +0x3EA bit 2; Thing_ModifyHealth(target, blow, attacker word +0x28, 0); attacker def+0x686 bit 14 and target type +0x36F == 0x1C (Stone Knight, creature only) -> 0x00490120. So a shot loses Health (lifetime/hits, shot def +0x47) and a body loses its rot lifetime (seeded DeadBodyDiesAfterSeconds x 4) by the blow; nothing else happens to either here. Finally, attacker def+0x686 bit 14 and target vtable +0x28 (0x004B5C30, health <= 0 for objects, shots and bodies) -> attacker KickToState(0xEF) (0x004992BD); sound 0xDB in bank def+0x6E3 at the attacker.

Read as assembly from 0x0058ADC0 to 0x0058AF6F; the second of the two projection sinks (the other is 0x0058AF70). It is the target of 0x0058AD10 (Vertex_ProjectThroughTemporaryTransformAlt), chosen by Renderer_SelectVertexSinks when its sixth argument is non-zero, together with TriSink_CullAndEmit (no clipping, no distance cull); 0x0058BB60 also calls it on the vertices it creates. Takes (slot index, pointer to x, y, z). Writes the vertex slot of table 0x0076F358 (0x28 bytes a slot): +0x00..+0x08 the input triple, +0x0C sx, +0x10 sy, +0x14 depth, +0x18 rhw, +0x1C outcode (always 0 here), +0x24 fade word, and a per-vertex flag byte in 0x0077F4F8. halfW and halfH are 0x0077F4CC and 0x0078093C, the centre is 0x0077F4F0 and 0x0077F930 (centre + 0.25). The input is already scaled by f/halfW and f/halfH after the rotation (matrix 0x0077F3A8), so sx = cx + 0.25 + f*X/Z; no term depends on the distance from the centre. Depth: z <= 0.5 gives [0x0077F490]*z + [0x0077F4D0]; z > 0.5 gives [0x007793A0] - [0x0077F934]*(1/z); then a clamp to at most 0.99993896. Frame flag bit 3 (0x0077F450, set in camera modes 2, 10, 11 and the path mode 0x12) adds the fade: D = z + 0.5*(|x|+|y|), t = 2*(V - D)/V with V = 0x0077F4E8, 2/V = 0x0077F4E0 and the double -0.5 at 0x0066FE80; t < 0 gives fade word 0 and flag 0x10, 0 <= t < 1 gives fade word floor(65536 t) (magic-number rounding with -0.49999) and flag 0x10, t >= 1 changes nothing. The fade word is applied to the vertex colour by Vertex_PackDiffuseAndFloatUv 0x0058B440 and the fixed-UV packer 0x0058B680 (possession-warp.md section 4).

It allocates the seven-player array through 0x00634E80 (heap allocation with flags zero, no explicit clearing found) and writes each record's id byte +0x10FC as index + 1, so the third record at +0x224A is player 3, the first keeper (steal-gold.md §2). The ids go onto a free list; activation (0x004C2460) later moves a player to the head of the active list, which is why the active list runs in reverse activation order (computer-keeper-threat.md §1). trigger-state.md §1 places the only store to 0x006E5054 at 0x004C1EA9, inside this function, from a constructor parameter; a live read showed that global and 0x006E5050 both hold the world object (Q231).
